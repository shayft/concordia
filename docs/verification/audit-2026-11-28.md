## 两种派发方式

在 Linux 执行 `pnpm benchmark:delivery`。运行两次相同的六卡“按负责人筛选”任务。每次执行数均为 6，主卡的三条验收条件和四个必需槽位的正文完全相同。

| 指标，单位为模拟秒 | 整卡串行 | 阶段性交付 |
| --- | ---: | ---: |
| 前端开始 | 9 | 2 |
| 总工期 | 26 | 15 |
| 至少一张卡在等依赖的时间 | 22 | 12 |
| 至少一张就绪卡在排队的时间 | 14 | 0 |
| 至少一张卡在等用户验收的时间 | 6 | 5 |

每类时间取并集。多张卡同时等待的同一秒只计一次。不同指标可以重叠。固定的工作时长、每卡一秒的验收延迟和接口发布时间均可从脚本输出复核。个人试用时，在同一任务中另记真实模型、返工、人工审批用时和实际账单，再判断收益。

## 受控负载

Linux 运行 `pnpm exec vitest run --reporter=verbose --silent=false apps/server/test/event-history.test.ts`，1 项通过。临时 WAL 库中创建 100 张任务卡和 10,000 条历史事件。随后对正式任务进度写入、读取看板和获取最新 100 条历史分别采样 40 次。该次运行的中位数和第 95 百分位如下，单位为毫秒。

| 操作 | P50 | P95 |
| --- | ---: | ---: |
| 写入一条任务进度 | 0.94 | 2.75 |
| 读取看板 | 0.40 | 1.08 |
| 读取最新一页历史 | 0.17 | 0.32 |

测试还核对前后分页的边界，以及订阅输出缓冲满时停读、恢复后连续收到全部 105 个事件。以上数据取自本次云端 Linux 文件系统，未设置跨硬件性能阈值。
