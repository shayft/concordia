# 分工提议、交付耗时与历史负载

2026-11-28，在 Linux x64、Node.js v24.19.0 下实测。调度对比使用注入时钟，HTTP 负载使用本机单调时钟和临时磁盘 SQLite。全部成员为模拟成员。

## 分工提议

**模拟测试通过。** 执行 `node_modules/.bin/vitest run apps/server/test/proposal-review.test.ts apps/web/test/workspace-ui.test.tsx packages/store/test/workflow.test.ts`，3 个文件，58 项通过。分工提议实现在提交 `65958c0`。

- 经实际本机服务和已认证会话，两个待决定提议分别预览，批准新增后，旧修订下的改派批准收到 HTTP 409。刷新后能批准改派并保留之前的执行记录。
- 在运行中或所见目标执行已改变时，批准不能生效。缺少负责人角色的成员不能提出变更。已有同名任务的旧提议仍可拒绝。
- 服务重启前后的重复批准、拒绝与动作重投只产生一项变更。历史提议缺少原始修订时显示“未知”。超过卡片标题长度的任务说明仍保留全文。
- DOM 测试验证看板显示差异，运行期间可拒绝提议，刷新后批准请求携带显示的计划和修订。

## 经本机 HTTP 测量的 100 张卡

**模拟测试通过。** 执行 `node_modules/.bin/tsx apps/server/bench/workflow-load.ts`，两组均通过存量、执行归属、验收和分页断言。命令也可通过 `pnpm benchmark:load` 运行。

两组均有 10 位模拟成员、10 条各含 10 张卡的依赖链。为保持早期历史基数一致，每组先批量写入 10,000 条历史事件。随后通过正常领取、两次发布、发送消息、提交和返工建立执行历史、带上游版本的交付物、收件箱和幂等回执。每组重启本机服务，经一次性链接建立会话，预热看板和历史读取，再依次对 40 张卡派发模拟执行并按所见执行验收。

| 采样前规模 | 每卡 1 轮 | 每卡 3 轮 |
| --- | ---: | ---: |
| 执行 / 交付版本 / 消息 | 100 / 200 / 100 | 300 / 600 / 300 |
| 幂等回执 / 历史事件 | 400 / 10,781 | 1,200 / 12,341 |
| 采样后执行 / 交付版本 / 已验收卡 | 140 / 240 / 40 | 340 / 640 / 40 |

每项操作采样 40 次。表格记录 P50 / P95，单位为真实毫秒，百分位取排序后第 20 / 38 个样本。计时包含本机 TCP、会话和工作区校验、服务处理、接收并解析 JSON。客户端使用相同顺序逐项发起请求。

| HTTP 操作 | 每卡 1 轮，P50 / P95 | 每卡 3 轮，P50 / P95 |
| --- | ---: | ---: |
| 启动模拟执行并收到响应 | 23.78 / 30.47 | 55.29 / 70.28 |
| 读取完整看板并核对所见执行 | 7.65 / 8.36 | 14.57 / 19.89 |
| 确认所见执行 | 6.69 / 9.31 | 13.94 / 19.45 |
| 读取最近 100 条历史 | 2.16 / 2.78 | 2.30 / 2.72 |

| 看板 SQLite 文件大小（字节） | 每卡 1 轮 | 每卡 3 轮 |
| --- | ---: | ---: |
| 采样开始 WAL | 0 | 0 |
| 每张卡完成后观察到的最大 WAL | 4,457,872 | 4,927,552 |
| 采样结束时 WAL | 4,457,872 | 4,927,552 |
| 采样结束时数据库主文件 | 1,585,152 | 2,822,144 |

这组数值反映当前 Linux 文件系统、短文本制品和单一顺序客户端的表现。WAL 大小包含 SQLite 复用的空间，仅在每组四个请求结束后取样。数据库大小仅含看板主文件，CAS、目录库及其 WAL 单独存储。本次同时增加了执行、交付版本、消息和回执，单一因素的贡献、浏览器渲染耗时和多窗口并发性能均尚未验证。
