# 工作区保留与离线清理

机主可查看单个工作区的保留清单，再决定是否回收旧的、已核实无引用的正文文件。命令从所用版本的项目根目录运行，适用于源码归档和 Git 检出。默认保留期为 30 天，可选 1 至 36,500 天。时间按对象文件的最近修改时间计算。仍受引用的对象长期保留。

先在运行服务的终端按 Ctrl+C 并等候退出，确认遗留进程已经在服务中核对。准备可恢复的本地备份。使用自己数据根的绝对路径和实际工作区标识运行预览，例中的 `default` 是初始工作区。[查找数据目录和备份](operations.md)

```sh
pnpm exec tsx apps/server/src/retention.ts preview --data-dir "应用数据根绝对路径" --workspace default --keep-days 30
```

预览 JSON 中的 `inventory` 汇总当前与归档计划里的任务、执行、版本、问答及提议，另外列出历史事件、规划请求及草案计数或状态。`entries` 逐个列出正文的 SHA-256、字节数、修改时间及保留原因。目录库有对正文的引用时也予以保留。为保住潜在引用，普通材料中的摘要也按引用处理。在一次清理中，即使父对象已经过期，它引用的子对象仍然保留。应用数据根、所选工作区或对象目录中出现当前发行版未知的存储项时，全部候选均保留。预览不会输出正文、账户、收件人或凭据值。

核对 `eligible`、`eligibleBytes` 和具体摘要后，保持同一版本、数据根、工作区及保留期，传入刚取得的 `previewId`。这一步会删除已列出的文件。目录、对象或候选清单发生变化时，重新预览后再决定。文件系统故障可能使已确认的清理只完成一部分，可重新预览剩余项。

```sh
pnpm exec tsx apps/server/src/retention.ts clean --data-dir "应用数据根绝对路径" --workspace default --keep-days 30 --confirm "本次预览编号"
```

| 数据 | 保留范围 |
| --- | --- |
| 工作区 SQLite、草案、提议、治理审计、历史事件和生成计划 | 本工具保留全部记录，包括当前工作区之外的目录库登记。可删除的文件仅在所选工作区的 `objects` 目录中。 |
| 其他工作区、联调及外部 Git 仓库 | 各自持有工作树、分支、提交及未提交修改。清理由原项目的工作树操作和 Git 管理。 |
| 原生 Claude Code、Codex 的会话、登录、配置及供应方账单 | 保留在原生应用、账户及供应方系统。 |
| macOS Keychain、Windows Credential Manager、Linux Secret Service | 由相应系统和账户管理。工作区清理保留凭据条目。 |
| 已导出的备份及团队自行保存的副本 | 各副本有独立保留期。原数据根清理不会传播，备份目录不能作为本命令的清理目标。 |

服务锁、工作区登记、实际数据库结构、迁移、WAL 事务及 SHA-256 对象完整性均须核对。新版本迁移加入其他引用形式后，需要在相应版本中复核再开放清理。需要删除仍被历史引用的个人材料时，应按数据处置要求单独处理工作区、备份与外部系统。
